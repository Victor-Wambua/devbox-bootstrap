macOS, bash 3.2+, MIT licensed

Your laptop setup, written down and checkable.

devbox is an idempotent bootstrap for developer Macs. Plan shows what would change. Apply changes only that, and running it again changes nothing. Doctor tells you what is missing or has drifted.

Setup that lives in someone's head

A new laptop is a day of installing and tweaking. Two people on the same team end up with different PHP versions and different PATHs. When a laptop dies, the answer to "how was it set up?" goes with it.

The usual fixes are a wiki page that rots or a shell script that only works once. devbox keeps the setup in small manifest files in git, and every step knows how to check itself, so it is safe to run again whenever you like.

What a profile looks like

# node: Node.js through fnm, tracking the current LTS.
summary: "Node.js via fnm, tracking the current LTS"
include: base

formula fnm min=1.35 why="Fast Node version manager"
block fnm-shell file="~/.zshrc" line="eval \"$(fnm env --use-on-cd --shell zsh)\"" why="Switches Node version per project"
cmd node-lts run="fnm install --lts" check="fnm list | grep -Eq 'v[0-9]+[.][0-9]+'" why="Installs the current LTS release"

Four rules the tool keeps

A tool that edits your dotfiles has to earn trust. These are the properties the tests pin down.

  1. 01

    Plan before apply

    devbox with no arguments is plan. It prints the exact command for every change, and with --dry-run the tests assert that nothing on the machine moved.

  2. 02

    Idempotent steps

    Every step has a check. Apply runs only unsatisfied steps, then re-checks. The second run is a no-op, for every bundled profile.

  3. 03

    Managed blocks

    Shell config edits live between begin and end markers and are replaced in place, never appended twice. Your own lines are left alone.

  4. 04

    Backups and a log

    Files are copied to ~/.devbox/backups/ before they change, macOS defaults get a restore script, and every run appends to a log.

Managed blocks, not appended lines

Re-running a script that does echo ... >> ~/.zshrc adds the line again each time. devbox writes a region with markers and replaces that region on the next run. If you edit inside it, doctor reports drift and apply puts it back. If the markers are damaged, devbox refuses to guess and tells you to fix it by hand.

This is the dotfile from the sandbox after one apply, with three lines of the user's own above the block.

$ cat ~/.zprofile
# my own settings
alias ll="ls -lah"
export EDITOR=vim

# >>> devbox:homebrew-shellenv >>> managed by devbox; edits between the markers are overwritten
if [ -x /opt/homebrew/bin/brew ]; then eval "$(/opt/homebrew/bin/brew shellenv)"; elif [ -x /usr/local/bin/brew ]; then eval "$(/usr/local/bin/brew shellenv)"; fi
# <<< devbox:homebrew-shellenv <<<

Profiles

Each profile is a manifest in profiles/. They can include each other. This table, and every page behind it, is generated from the manifests. Steps counts everything a profile resolves to, included profiles too.

What it does not do

  • It is macOS only. It refuses to run elsewhere, and refuses to run as root.
  • It has been exercised against a mocked brew, defaults and friends, not end to end on a clean Mac. Real installs, and Laravel Valet's real behaviour, are unverified.
  • It does not install Homebrew for you. It tells you where to get it, rather than piping an installer into a shell.
  • It manages what a profile declares. It will not discover and remove things you installed by hand.
